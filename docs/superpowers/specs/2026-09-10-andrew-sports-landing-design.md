# Лендинг персонального фитнес-тренера Андрея Снегурова — дизайн-документ

Дата: 2026-09-10
Источник дизайна: Figma `0tu6M8MX5ruypVWv5f1bV8`, фрейм `8:275` (390×3816) + слайды отзывов `8:421` / `8:438` на канвасе.

## 1. Цель и рамки

Одностраничный лендинг, на котором посетитель:

1. понимает, кто такой Андрей и чем он полезен;
2. видит подход, услуги и реальные результаты клиентов;
3. одним нажатием попадает в личную переписку с Андреем в Telegram.

Формы обратной связи, оплаты, личного кабинета, блога и мультиязычности **нет** — вся конверсия идёт в Telegram.

## 2. Технические решения

| Решение | Значение | Почему |
|---|---|---|
| Стек | HTML5 + CSS3 + vanilla JS | Как в соседнем проекте `wedding`; ноль зависимостей, ноль сборки, деплой копированием файлов |
| Подход к вёрстке | Mobile-first | Макет нарисован под 390px; десктоп — надстройка |
| Хостинг | GitHub Pages / Netlify / Vercel | Статика, бесплатно |
| Шрифты | Локальный TTF + Google Fonts | `Electrolize [RUS by Daymarius]` (дисплейный, файл заказчика) + `Montserrat Alternates` (текст) |
| Локальный просмотр | `.claude/dev-server.js` на Node | Без зависимостей, порт 5173 |

Внутри каждого файла границы держим комментариями-разделителями по секциям; порядок блоков в CSS и JS совпадает с порядком секций в HTML.

### Свечения

Шесть размытых синих кругов на фоне (в макете — `Ellipse 2/3/5/6/7/8`). Реализация: `div` с `background: var(--accent)`, `border-radius: 50%`, `filter: blur(129.6px)`. Значение взято из SVG-экспорта Figma (`feGaussianBlur stdDeviation="129.6"`); CSS `blur()` использует ту же величину как σ, поэтому совпадение точное.

Позиции (координаты фрейма 390×3816; в вёрстке привязываются к своим секциям, а не к абсолютному `top` страницы):

| # | Позиция в макете | Диаметр | Привязка в вёрстке |
|---|---|---|---|
| 1 | x 256, y −7 | 161 | hero, справа сверху |
| 2 | x −33, y 508 | 161 | блок слогана/CTA, слева |
| 3 | x −53, y 1436 | 154 | «Мой подход», слева |
| 4 | x 268, y 2004 | 154 | «Услуги», справа |
| 5 | x −71, y 2935 | 154 | «Отзывы», слева |
| 6 | x 263, y 3662 | 154 | «Контакты», справа |

Все свечения — `aria-hidden`, `pointer-events: none`, лежат под контентом с `z-index: -1` (нулевой уровень у позиционированного элемента красился бы поверх текста). Тем, что в макете прижаты к правому краю (1, 4, 6), в разметке ставится класс `glow--right`: от 768px они привязываются к правому краю экрана, иначе фиксированные пиксельные координаты макета 390px увели бы их в середину широкого экрана.

### Обрезка боковых выносов

За края экрана намеренно выходят: свечения (правые доходят до x=422 при ширине 390), номера 01–04 (§4.5), размытая копия hero-фото. Само по себе это сделало бы страницу шире экрана — а тогда не только появляется горизонтальная прокрутка, но и **фиксированная полоса меню растягивается по ширине области прокрутки** (422px вместо 390) и её пункты уезжают вправо.

Поэтому: `overflow-x: clip` на `.section`. Именно `clip`, а не `hidden` — `hidden` превратил бы `overflow-y` в `auto` и дал бы каждой секции собственную вертикальную прокрутку. Обрезка только по горизонтали, поэтому свечения по-прежнему свободно растекаются по вертикали между секциями и не получают резаного края. На `html` продублирован `overflow-x: hidden` + `overflow-x: clip` — запасной вариант для браузеров без поддержки `clip`.

### 4.1 Навигация

### 4.2 Hero

- Фото Андрея во всю ширину, высота 404px (соотношение 390:404).
- **Ассет обязан быть вырезкой с прозрачным фоном** (alpha = 0 вокруг фигуры). Экспорт узла из Figma этого не даёт — он склеивает вырезку на белом; исходник берётся из `rawImages` и масштабируется. Если фон непрозрачный, за фигурой пропадают синяя ломаная, свечение и фон страницы, и hero выглядит сломанным.
- Позади фото — **чёрный силуэт** той же вырезки (`hero-shadow.png`: альфа-канал фото, залитый чёрным), размытый (`blur(7px)`), `opacity: .38`, сдвинутый на 13px вправо и 6px вниз. В макете это отдельный слой-картинка с тёмным силуэтом; по замеру рендера он темнит фон у правого края фигуры примерно на 30% в полосе ~15px. Копия самого фото (первая версия) даёт светлый ореол от белой футболки — ровно противоположный эффект.
- Поверх — SVG-ломаная `hero-lines.svg` (обводка `--accent`, 0.8px), `aria-hidden`.
- Справа: `АНДРЕЙ` / `СНЕГУРОВ` (`<h1>`, 32px, `--accent`, выравнивание по правому краю) и под ним `персональный` / `фитнес-тренер` (13px, белый).
- Под фото — полоса `--accent` во всю ширину, высота 8px.

## 5. Поведение (JavaScript)

`script.js` состоит из трёх независимых модулей, каждый — самовызывающаяся функция с одной задачей. Ни один не знает о других; каждый начинается с проверки, что его элементы есть в DOM, поэтому падение одного не ломает остальные.

### 5.1 Плавный скролл

CSS-свойство `scroll-behavior: smooth` на `html` плюс `scroll-padding-top: 42px` — компенсация высоты фиксированного меню. JS не нужен.

### 5.2 Подсветка активного пункта меню

Обработчик `scroll` (троттлинг через `requestAnimationFrame`) определяет последнюю секцию, чьё начало уже прошло под нижним краем меню, и ставит её ссылке класс `is-active` и `aria-current="true"`, снимая их у остальных.

Отдельное правило для низа страницы: если прокрутка дошла до конца, активным всегда считается последний пункт. Без него подсветка застревает на «отзывах» — секцию «Контакты» физически нельзя доскроллить до верха экрана, под ней просто нет контента.

Изначально здесь планировался `IntersectionObserver`, но случай «последняя секция» он не покрывает: никакого пересечения при доскролле до конца не происходит, и наблюдатель не срабатывает. Прямой расчёт от `scrollY` короче и предсказуемее.

### 5.3 Карусель отзывов

Собственная реализация без библиотек, построенная **на нативном горизонтальном скролле** со `scroll-snap`, а не на `transform`.

Разметка: контейнер `.reviews-track` (`display: flex; overflow-x: auto; scroll-snap-type: x mandatory; scrollbar-width: none`) с тремя `.review-slide` (`flex: 0 0 100%; scroll-snap-align: center`).

Почему так, а не через `translateX`:

- свайп пальцем — родной, с инерцией и «резинкой», без ручной обработки Pointer Events (минус ~50 строк кода и весь класс багов с перехватом вертикального скролла);
- **карусель полностью работает при выключенном JS** — слайды листаются пальцем и трекпадом; JS добавляет только индикаторы, стрелки и клавиатуру;
- скроллбар скрывается стилями, но остаётся доступным для скринридеров и клавиатуры.

Управление, которое добавляет JS:

| Ввод | Поведение |
|---|---|
| Клик по индикатору | `scrollTo` к соответствующему слайду (`behavior: smooth`) |
| Стрелки ← / → (только ≥768px) | Предыдущий / следующий |
| Клавиши ← / → при фокусе на карусели | Предыдущий / следующий |
| Скролл трека (в том числе свайп) | Слушатель на `scroll` с `requestAnimationFrame`-троттлингом пересчитывает активный индекс из `scrollLeft` и обновляет индикаторы |

Отдельно скрипт подгоняет высоту `.reviews__viewport` под активный слайд. Отзывы сильно разной длины: самый длинный втрое выше самого короткого, и без подгонки под коротким отзывом остаётся около 200px пустоты. Для этого у трека стоит `align-items: flex-start` — иначе flex растянул бы все слайды по высоте самого высокого и мерить было бы нечего. Высота пересчитывается по `ResizeObserver` на треке и после `document.fonts.ready`. Без JS высота остаётся авто (по самому высокому слайду) — карусель при этом полностью работоспособна.

Переход зациклен: с третьего слайда «вперёд» ведёт на первый. Автопрокрутки нет — на отзывах она отбирает у читателя управление посреди чтения.

Доступность: контейнер `role="region"` + `aria-roledescription="carousel"` + `aria-label="Отзывы"` + `tabindex="0"` (чтобы скроллился с клавиатуры); каждый слайд — `role="group"`, `aria-roledescription="слайд"`, `aria-label="1 из 3"`; индикаторы — настоящие `<button>` с `aria-label` и `aria-current`. `inert` на невидимых слайдах **не ставится**: при нативном скролле все слайды остаются в потоке и должны быть достижимы вкладкой.

### 5.4 Появление секций при скролле

`IntersectionObserver` добавляет класс `is-visible` блокам с атрибутом `data-reveal`, когда они входят в кадр на 15%. CSS переводит их из `opacity: 0; translateY(16px)` в нормальное состояние за 500ms. Наблюдение снимается после первого срабатывания.

Важно, как именно это включается. Правило записано как `.js-enabled [data-reveal] { opacity: 0 }` внутри `@media (prefers-reduced-motion: no-preference)`, а класс `js-enabled` скрипт вешает на `<html>` первой же строкой. То есть начальная прозрачность **появляется только при живом JS** — при выключенном JS класса нет, правило не применяется и контент виден сразу. Страница не может «остаться пустой»: чтобы что-то спрятать, сначала должен выполниться скрипт, который это же и покажет.

## 6. Адаптивность

Mobile-first, три брейкпоинта.

### ≤767px — базовый (точная копия макета)

Контейнер 390px (при большей ширине — 100%), внутренние поля 27px. Все секции в одну колонку, порядок как в §4.

### ≥768px — планшет

- Контейнер 720px, поля 32px, размеры шрифтов растут примерно на 15%.
- «Мой подход»: сетка 2×2. Вынос номеров за левый край экрана **здесь же и выключается**: в двух колонках правая колонка наезжала бы на левую. Номера прижимаются к левому краю своей ячейки и уменьшаются до 56px.
- «Услуги»: остаются в одну колонку, но карточки ограничены `max-width: 480px` и центрированы. Две колонки на этой ширине дают либо карточку-сироту в половину ряда, либо растянутую на всю ширину третью — обе выглядят хуже, чем ровная колонка. Три в ряд появляются только на десктопе.
- Отзывы: появляются боковые стрелки; фото слайда 240×240.

### ≥1024px — десктоп

- Контейнер 1120px, поля 40px.
- Hero: две колонки — слева фото (высота 560px, радиус 16), справа имя, подзаголовок, слоган и CTA-кнопка. Синяя полоса 8px остаётся под всей секцией.
- «Мой подход»: сетка 2×2, как на планшете.
- «Услуги»: три карточки в ряд, равной высоты (`align-items: stretch`).
- «Обо мне»: текст и фото-с-цитатой в две колонки.
- «Контакты»: три кнопки в ряд.

## 7. Доступность

- Семантика: `<header>` с `<nav>`, `<main>`, пять `<section>` с `aria-labelledby`, `<footer>`.
- Один `<h1>` (имя в hero), заголовки секций — `<h2>`, заголовки пунктов и карточек — `<h3>`.
- У всех фото осмысленный `alt`; декоративная графика — `alt=""` + `aria-hidden="true"`.
- Видимый фокус: `:focus-visible` — обводка 2px `--accent` со смещением 2px; на синих кнопках белая, чтобы не сливалась.
- Тач-цели. Кнопки в макете ровно 44px — сохраняем. Пункты меню видимо остаются 61×30 (полоса меню по макету ровно 42px), но область нажатия расширена невидимым псевдоэлементом `::after { inset: -7px -10px }` до 81×44. Индикаторы карусели — исключение: видимый штрих по макету 38×3, кнопка добирается вертикальным паддингом до **38×45**. По ширине это меньше 44: сделать их шире можно только за счёт наложения соседних зон или изменения рисунка макета. 38×45 с запасом проходит WCAG 2.5.8 Target Size (Minimum, AA) — там порог 24×24.
- `prefers-reduced-motion: reduce` отключает появление секций и анимацию перехода карусели (переключение остаётся мгновенным).
- Контраст, честные цифры:
  - `#008CFF` на `#111` — **5.6:1**, проходит AA для любого текста; этим цветом набраны заголовки, подзаголовки пунктов и короткие акценты;
  - основной текст белым на `#111` — **17.6:1**;
  - белый на `#008CFF` (надписи на кнопках 16px и пункты меню 13px) — **3.4:1**. Это проходит порог для крупного текста и элементов интерфейса, но **не проходит AA для мелкого текста** (нужно 4.5:1).

  Последнее — прямое следствие фирменной пары цветов из макета. Менять её самостоятельно нельзя: это решение владельца бренда, а не разработчика. Реализовано как в макете, вопрос вынесен в `TODO.md` вместе с готовым вариантом решения (затемнить фон кнопок и меню до ≈`#0064CC`, что даёт 4.6:1).

## 10. Проверка

Работа считается сделанной, когда выполнено всё перечисленное и это подтверждено запуском, а не рассуждением.

1. **Сверка с макетом.** Скриншот сайта на ширине 390px рядом со скриншотом фрейма Figma; расхождения по вертикальному ритму, размерам и цветам разбираются поштучно.
2. **Адаптив.** Скриншоты на 390 / 768 / 1440. Ничего не наезжает и не обрезается; горизонтальной прокрутки нет ни на одной ширине.

   Проверять именно прокрутку, а не `scrollWidth`: при `overflow-x: clip` браузер продолжает сообщать `scrollWidth` больше `clientWidth`, хотя страница не прокручивается. Достоверная проверка —

   ```js
   scrollTo(200, 0); await new Promise(r => setTimeout(r, 250)); scrollX !== 0
   ```

   должно вернуть `false`. Заодно стоит убедиться, что полоса меню шириной ровно во вьюпорт: `document.querySelector(".nav").getBoundingClientRect().width === document.documentElement.clientWidth`.
3. **Карусель.** Свайп, клик по индикаторам, стрелки, клавиатура, зацикливание — вручную в браузере.
4. **Меню.** Клик по каждому пункту прокручивает к своей секции; активный пункт меняется при скролле.
5. **Ссылки.** Каждая CTA-кнопка — это `<a>` с непустым `href`, открывается в новой вкладке.
6. **Консоль.** Ноль ошибок и предупреждений при загрузке и при взаимодействии.
7. **Без JS.** При отключённом JavaScript видны все секции и работают все ссылки. Плавный скролл при этом сохраняется — он чистый CSS (§5.1), JS для него не нужен. Теряются только подсветка активного пункта меню, индикаторы/стрелки/клавиатура у карусели и подгонка её высоты под активный слайд; сами слайды остаются доступны — трек скроллится по горизонтали нативно.
8. **`prefers-reduced-motion`.** При включённой настройке анимаций нет, контент виден сразу.

## 11. Осознанно не делается

- Бургер-меню — четыре коротких пункта помещаются на любой ширине.
- Автопрокрутка карусели.
- Форма обратной связи — вся конверсия в Telegram, так задумано заказчиком.
- Сборщик, препроцессоры, фреймворки, CSS-библиотеки.
- Тёмная/светлая темы — сайт по дизайну всегда тёмный.
